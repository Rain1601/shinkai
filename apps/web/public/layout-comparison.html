三种 layout 方案对比

同一份数据 · 同一个 anchor (NVIDIA) · 三种"当前层 + ±1 层"呈现
场景:用户当前 anchor =NVIDIA (L4 Company)。希望只看同层(其他公司)的关系,但同时知道 NVIDIA 的父层(L2 主题)是 AI Infra / Physical AI / AI Models,子层(L5 产品)是 B300 / Rubin / Vera / GB200。点击任意 ±1 层节点 → drill 切换层级。
A

Top / Bottom Rail

主图永远只显示当前层公司 + 同层关系。父层在顶条带,子层在底条带,各以 chip 列出,可点击 drill。

特点
  • 主图永远只一个 facet(L4 公司 + 价值链关系),视觉干净
  • "我在哪一层"用条带位置 + 颜色直接告知
  • ±1 层 chip 单击 drill,无需在 graph 里找节点
  • 与现有 Strata strip 兼容,左侧仍然显示价值链行
PROS
  • 实施简单,与当前架构兼容
  • 视觉负担最小
  • chip 数量多时可水平滚动
CONS
  • 父/子层用 chip 表达,失去"节点间关系"信息
  • 跨多层 drill 时(L4 → L6)需多次点击
B

Finder Column View

三列布局,左父右子,中间是当前层 graph。像 macOS Finder Column 一样可层层"进入",列表式导航。

特点
  • 像文件管理器一样的层级 navigation
  • 左列 list 显示所有可下钻的父层,右列同理
  • 中间列是当前层 graph + 当前 anchor 在 list 中高亮
  • 点击右列任一行 = 立即 drill into 该节点
PROS
  • 层级关系最清晰,navigation 体验最强
  • 支持同时浏览多层(扫一眼父/子列表全貌)
  • 已经习惯 macOS Finder 的用户秒上手
CONS
  • 中间 graph 区域被压窄(只占中间 1/3)
  • 失去"graph 全屏"的视觉爽感
  • 实施复杂(三个独立 panel + 状态同步)
C

Satellite Nodes

父/子层节点仍在 graph 内,但用极淡的视觉(半透明 + 虚线边)表达"不是主角",拉到顶部/底部边缘漂浮。

特点
  • 主图仍是一张完整 graph,层级感用透明度 + 边缘位置表达
  • 父/子节点半透明 + 虚线连接,视觉上"次要但存在"
  • hover 父/子节点会变实(显眼),点击 drill
  • themed_under / produces 用极淡虚线连接父/子和 anchor
PROS
  • graph 完整性最高,所有节点和边都在视图里
  • 层级关系视觉化(虚线可见)
  • 不破坏现有 graph 美学
CONS
  • 多 facet 仍然混在同一画布,视觉负担最大
  • 跨层多节点时(如 L2 有 5 个,L5 有 10 个)边缘会很挤
  • "哪些是当前层、哪些是 ±1 层"靠透明度区分,新用户需要适应
