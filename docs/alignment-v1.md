## 一、项目定位

### Q1.1 项目名 "shinkai" 的含义是什么?
**深海(しんかい)** — 取深邃、神秘、未知的意境。区别于其他读法:
- 新海(姓氏,如动画导演新海诚)
- 神界(神域)

### Q1.2 shinkai 与上一个项目 uteki 的关系?
| | uteki | shinkai |
|---|---|---|
| 对象 | 主流公司 | 深度领域 / 标的 |
| 方向 | 意图分析 | 深度调研 |
| 形态 | 广而浅 | 深而专 |
| 类比 | 扫描 | 潜水 |

shinkai 是 uteki 的深度延伸,定位互补。

### Q1.3 shinkai 解决什么问题?
**深度投研** — 替人/与人协作进行**自主、持续、高质量**的深度研究。
不做市场扫描,不做新闻聚合,做**深度判断**。

## 二、Agent 设计哲学

### Q2.1 Agent 的本质是什么?
最简定义:`LLM + 工具 + 循环 + 上下文管理`。

但本质不在于"会用工具",而在于**自主判断**:
- 该不该停
- 该不该问人
- 该不该改方向
- 该不该承认自己错了

### Q2.2 一个"好"的 Agent 应该像什么?
**像一个学霸 / 优秀研究员 / 大师**(巴菲特、芒格、纳瓦尔)。

核心特质:**用心智模型思考、有长时间视野、能复利知识、对"什么值得研究"有 taste**。

### Q2.3 一个好的 Agent 由哪些模块构成?

| 模块 | 类比 | 层 |
|------|------|------|
| 脑子(模型) | 学霸的脑容量 | 执行层 |
| 自主性 / 主动探索 | 学霸的求知欲 | 执行层 |
| 工具 | 学霸两支笔 | 执行层 |
| 记忆 | 学霸的记性 / 记忆宫殿 | **核心层** |
| 评测 + 正向反馈 | 考试与进步 | **核心层** |
| 导师 / 成长环境(harness) | 学霸的老师 / 环境 | **核心层** |
| 自我迭代 / 自我进化 | 学霸的成长 | **核心层** |
| **任务设定**(本次新增) | "什么算做完了" | **核心层** |
| **可观测 + 可评测**(本次新增) | 能被人理解和测量 | **核心层** |

### Q2.4 "执行层"和"核心层"的关键判断
> **脑子 + 工具是执行层(随时间趋于商品化);记忆 + 评测 + 导师 + 环境 + 迭代是核心层(差异化的来源)**

设计资源应当向核心层倾斜。

## 三、架构原则(shinkai 的五条第一性原则)

### 原则 1 · 人 ↔ 中间层 ↔ Agent 系统/Agent 执行
**主流方案的根本缺陷**:OpenAI Operator / Claude Computer Use 让 Agent 直接 puppet 人的桌面。后果:
- 人被锁定,不能并行干别的
- 出问题难以回滚
- 无法并行多 Agent
- 观测=肉眼盯屏幕,等于没观测

**shinkai 的架构**:
- **Agent** 在自己的执行环境跑(沙箱 / VM / 远程 worker)
- **中间层** 承担三个职责:**可观测 + 可控制 + 可审计**
- **人** 通过中间层与 Agent 协商,不被 Agent 接管

### 原则 2 · 工具极简("学霸两支笔,差生文具多")
工具数量上升 → 模型选择压力非线性上升 → 描述污染上下文 → 组合爆炸 → 出错率上升。

**研究型 Agent 核心工具集(6-8 个)**:
- `web_search` / `web_extract`
- `read_doc` / `write_note`
- `grep_corpus`
- `compare` / `cite`
- `compute`(可选,算估值表)

### 原则 3 · 执行层 vs 核心层(资源向核心层倾斜)
见 Q2.4。**模型与工具是商品,记忆/评测/critic/迭代是护城河。**

### 原则 4 · 单 Agent 优先,多 Agent 现阶段不投入
多数所谓"多 Agent 胜利"其实是更好的上下文隔离。真正的 agent-to-agent 协商目前没有令人信服的案例。**先把单 Agent 在投研里做深做稳。**

### 原则 5 · 可观测 + 可评测(用户本次明确,升级为第一性原则)
- **可观测**:与人交互的基础(没有观测,人就无法理解、信任、介入)
- **可评测**:进化的基础之一(没有评测,迭代就是盲改)

> 所有架构决策都必须能回答:**"这个设计能被观测吗?能被评测吗?"** 不能回答的,需要重新设计。

## 四、核心能力模块的设计要点

### Q4.1 记忆系统怎么设计?
不只是"存什么",更是"取什么"和"何时巩固"。

**分层**:
- 工作记忆(当前任务上下文)
- 情景记忆(做过的研究、得出的结论)
- 语义记忆(学到的事实、公司画像)
- 程序记忆(学会的研究套路 — 如"消费股先看品牌护城河")

**关键难点 — Consolidation(巩固)**:什么时候把"发生过"变成"学会了"。多数 Agent memory 系统只做了 RAG,没做真正的学习。

**投研特有 — 时间衰减**:两年前的财报和昨天的财报权重不同。长记忆必须有时间感和有效期。

### Q4.2 评测怎么做?
两层:
- **外部评测**:人/系统检查 Agent 的研究质量
- **内部评测**:Agent 自我评估当前结论的置信度、覆盖度、矛盾点

### Q4.3 "导师"系统(harness + GAN 思想)怎么落地?
GAN 思想优雅但难落地(reward 太稀疏)。更实用的版本:
- **Critic Agent**:用更挑剔视角批评研究(如"巴菲特视角的 critic"、"做空者视角的 critic")
- **Bull/Bear Self-play**:同一标的让 Agent 给自己出反方观点,内部辩论
- **Replay**:同一输入多次运行,看分歧 — 分歧本身是不确定性的来源

### Q4.4 自我迭代现阶段可行吗?
真正完全自动的 self-improvement 仍是研究前沿。**现实路径**:
1. 先把人迭代回路做高效(可观测 + 可评测 → 人能精准发现 Agent 哪里弱)
2. 累积 critic / replay 数据
3. 再考虑用这些数据做自动化迭代

## 五、开放性难题深探

### Q5.1 长时间持续执行 + 上下文/目标偏移 + 多分支探索
**这三个其实是同一个问题**:Agent 怎么在不丢失方向感的前提下做开放性探索。

设计要点:
- **North Star Anchor**:核心研究问题做成常驻 artifact,每 N 步重新加载,强制重新定向
- **结构化的研究状态**(关键):不要让"研究进度"散在对话历史里。Agent 应维护一个**研究图谱文档**(已知 / 未知 / 待验证 / 已排除 / 置信度)— 这才是它真正的"心智地图",上下文只是缓存
- **多分支**:git 式 branching。每个假设一个分支,定期 merge / kill。**这必须在中间层调度**,不是 Agent 自己能管

### Q5.2 Agent 可观测的关键维度?
1. **意图链(intention trace)**:不是日志,是"为什么做这一步"的因果链
2. **置信度轨迹**:Agent 对当前结论的置信度怎么随证据变化(**投研里比结论本身还重要**)
3. **资源消耗**:token / 时间 / 成本 per insight
4. **可介入点**:哪些时刻人可以暂停、修改、注入新信息

### Q5.3 Agent 仿真 + Agent 社会化
**当前阶段不投入**。
- 仿真:投研有现成工具(backtest),Agent 调用即可
- 社会化(多 Agent 协作):被严重高估,等单 Agent 跑通再说

## 六、关键定义(用户回答 Q1 / Q2)

### Q6.1 shinkai 一次研究的输出形态?
**结构化数据(Markdown 或 JSON)+ 高质量人类可读文档 + 可被另一个 Agent 复用的研究图谱**

> 关键洞察:**未来 Agent 的产出不仅给人看,也需要给 Agent 看**。这印证了 Agent 间通信的重要性,也提前为后续多 Agent / Agent-to-Agent 场景留好接口。

设计含义:
- 输出格式必须**机器友好 + 人类友好**双重表达
- 每份产出本身就应该是可索引、可被检索、可被 critic Agent 读取的**研究资产**
- 这意味着 shinkai 的输出是一种**研究图谱(research graph)**,不只是报告

### Q6.2 "研究做完了"的边界条件?
**通过初始化 + 人参与的方式定义**:
1. 每次调研**开始前**,初始化一个完整的研究 checklist
2. **人可以确认**这个 checklist
3. 过程中**人可以干预、修改**
4. checklist 既是研究路径图,也是"完成"的判断标准

> 这把"何时停止"这个最难的开放问题,转化成了**人机协作的、可调整的、可观察的边界**。
> checklist 是中间层的一等公民 artifact。
